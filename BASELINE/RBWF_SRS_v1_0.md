## 1. บทนำ (Introduction)

**ระบบบริหารงานธุรกิจจัดจำหน่ายวัสดุก่อสร้างและกระเบื้องครบวงจร (Rabbit Workflow - RBWF)** จัดทำขึ้นเพื่อสนับสนุนกระบวนการทางธุรกิจของ บริษัท แรบบิท ไทล์ จำกัด โดยครอบคลุมการจัดการคลังสินค้าและสต็อกกระเบื้อง การออกคำขอใบเสนอราคาและใบเสนอราคา การจัดซื้อผ่านใบสั่งซื้อ การบริหารงานช่างและคิวส่งของ (Delivery Note) ตลอดจนระบบบัญชีเงินสด ค่าคอมมิชชัน เงินเดือน และสิทธิ์การใช้งานตามบทบาท (RBAC)

## 2. ความต้องการของระบบ (System Requirements)

### 2.1 ภาพรวมความต้องการของระบบ (System Requirement Overview)

ระบบออกแบบเป็น Web-Based Application ให้พนักงานขาย ฝ่ายจัดซื้อ ฝ่ายคลังสินค้า ช่างตัด/เตรียมกระเบื้อง ฝ่ายการเงิน และผู้บริหาร ทำงานบนระบบเดียวกัน สามารถบันทึกและติดตามงานตามโมดูลในเอกสาร SOW ข้อ 3.1–3.6 ตรวจสถานะเอกสาร และออกรายงานได้โดยไม่ต้องใช้ระบบแยกหลายชุด

### 2.2 ความสามารถของระบบ (Requirements Functionality)

รหัสข้อกำหนดสอดคล้องกับขอบเขตในเอกสาร SOW ข้อ 3.1–3.6 และสรุปในเอกสาร PMP ข้อ 2

#### 2.2.1 ระบบจัดการคลังสินค้าและสต็อกกระเบื้อง (Stock Management)

| Requirement ID | รายละเอียดความต้องการ |
|---|---|
| **REQ-STK-01** | ระบบสามารถเพิ่ม แก้ไข และลบหมวดหมู่และรายการสินค้ากระเบื้อง พร้อมระบุขนาด เกรด สี ราคา และตำแหน่งจัดเก็บ |
| **REQ-STK-02** | ระบบสามารถบันทึกรับเข้า-จ่ายออกสต็อกกระเบื้องและปรับปรุงยอด (Stock Adjust) |
| **REQ-STK-04** | ระบบสามารถส่งการแจ้งเตือนสินค้าคงคลังต่ำกว่าเกณฑ์ (Stock Notification) ผ่านระบบและอีเมล |

#### 2.2.2 ระบบคำขอใบเสนอราคา ใบเสนอราคา และคอมมิชชัน (RFQ, Quotation & Commission)

| Requirement ID | รายละเอียดความต้องการ |
|---|---|
| **REQ-QTO-01** | ระบบสามารถบันทึกและติดตามคำขอใบเสนอราคา (RFQ) จากลูกค้า |
| **REQ-QTO-02** | ระบบสามารถสร้างใบเสนอราคา (Quotation) คำนวณส่วนลด กำไรขั้นต้น (Profit Analysis) และออก PDF |
| **REQ-QTO-03** | ระบบมีเวิร์กโฟลว์การอนุมัติใบเสนอราคาตามมูลค่าอนุมัติ |
| **REQ-QTO-04** | ระบบสามารถคำนวณและบันทึกประวัติการจ่ายค่าคอมมิชชันสำหรับพนักงานขาย |

#### 2.2.3 ระบบใบสั่งซื้อและซัพพลายเออร์ (Purchase Orders & Suppliers)

| Requirement ID | รายละเอียดความต้องการ |
|---|---|
| **REQ-PO-01** | ระบบสามารถสร้างและออกใบสั่งซื้อ (PO PDF) ส่งไปยังซัพพลายเออร์ |
| **REQ-PO-02** | ระบบสามารถบันทึกการรับสินค้า (PO Receipts) พร้อมอัปโหลดรูปภาพและเอกสารกำกับ |
| **REQ-PO-03** | ระบบสามารถบันทึกการชำระเงินค่างวด PO ใบกำกับภาษี และเอกสารใบเสร็จ |
| **REQ-PO-04** | ระบบจัดการข้อมูลซัพพลายเออร์และประวัติการสั่งซื้อ |

#### 2.2.4 ระบบงานช่าง คิวจัดเตรียม และใบส่งสินค้า (Worker Jobs, Queue & DN)

| Requirement ID | รายละเอียดความต้องการ |
|---|---|
| **REQ-WRK-01** | ระบบสามารถมอบหมายงานช่าง (Worker Jobs) และติดตามสถานะการตัด/เตรียมกระเบื้อง |
| **REQ-WRK-02** | ช่างสามารถอัปโหลดรูปภาพผลงานหลังทำเสร็จ |
| **REQ-WRK-03** | ระบบสามารถแสดงผลหน้าจอคิวการเตรียมสินค้า (Queue Display Page) แบบเรียลไทม์ |
| **REQ-WRK-04** | ระบบสามารถออกใบส่งของ (Delivery Note PDF) และส่งแจ้งเตือนการจัดส่ง |

#### 2.2.5 ระบบการเงิน บัญชีเงินสด และสิทธิ์การใช้งาน (Finance, Cash Ledger & RBAC)

| Requirement ID | รายละเอียดความต้องการ |
|---|---|
| **REQ-FIN-01** | ระบบสามารถบันทึกสมุดบัญชีเงินสดรับ-จ่าย (Cash Ledger) และสรุปยอดคงเหลือ |
| **REQ-FIN-02** | ระบบสามารถบันทึกค่าใช้จ่ายองค์กร (Expenses) และคำขอเบิกจ่ายพนักงาน (Reimbursements) |
| **REQ-FIN-03** | ระบบคำนวณเงินเดือนพนักงาน (Salary Management) และออกใบเสร็จรับเงิน (Receipt PDF) |
| **REQ-FIN-04** | ระบบจัดทำรายงานสรุปผลการดำเนินงานและรายงานการเงินประจำเดือน |
| **REQ-SEC-01** | ระบบบริหารผู้ใช้งาน (Users), เอเจนต์ (Agents), พนักงาน (Workers) และผู้จัดจำหน่าย (Suppliers) กำหนดสิทธิ์ตามบทบาท (RBAC) และเปลี่ยนรหัสผ่าน |

### 2.3 ส่วนต่อประสานภายนอก (External Interfaces)

ระบบเชื่อมต่อกับบริการภายนอกเท่าที่จำเป็นต่อการทำงานตามข้อกำหนด ไม่ใช้ Payment Gateway หรือ Mapping API

- **SMTP / อีเมล**: ส่งการแจ้งเตือนสินค้าคงคลังต่ำกว่าเกณฑ์ตาม REQ-STK-04
- **WebSocket**: ส่งสถานะคิวเตรียมสินค้าแบบเรียลไทม์ไปยังหน้า Queue Display
- **ที่เก็บไฟล์**: จัดเก็บเอกสาร PDF (ใบเสนอราคา, ใบสั่งซื้อ, ใบส่งของ, ใบเสร็จ) และรูปถ่ายงานช่าง/ใบรับสินค้า
- **HTTPS ผ่าน Nginx และ Cloudflare**: รับส่งข้อมูลระหว่างผู้ใช้กับระบบตามเอกสารสภาพแวดล้อมการพัฒนา (IE)

## 3. ความต้องการทางซอฟต์แวร์ (Software Requirements)

### 3.1 ภาพรวมความต้องการทางซอฟต์แวร์ (Software Requirement Overview)

Rabbit Workflow พัฒนาเป็น Web Application โดยใช้ **Go REST API** ทำงานร่วมกับฐานข้อมูล **MySQL 8.0** ใช้ **Redis** ในการแคชข้อมูล และใช้ **Svelte / Vite** เป็นส่วนติดต่อผู้ใช้ ระบบทำงานในคอนเทนเนอร์ **Docker** ตามเอกสาร IE และ SDD

### 3.2 ความสามารถของระบบ (Requirements Functionality)

ระบบจะรองรับการทำงานดังนี้:

- รองรับผู้ใช้พร้อมกันไม่น้อยกว่า 50 Concurrent Users โดย Response time ของ REST API เฉลี่ยต่ำกว่า 500 ms และหน้าจอตอบสนองไม่เกิน 2 วินาที (REQ-NFR-02)
- ข้อมูลผู้ใช้ถูกปกป้องด้วยการเข้ารหัสรหัสผ่านแบบ bcrypt, JWT Token และสิทธิ์ RBAC (REQ-NFR-03)

### 3.3 ส่วนต่อประสานภายนอก (External Interfaces)

- ระบบให้บริการ **REST API (JSON)** ผ่าน Nginx Reverse Proxy สำหรับหน้าเว็บ Svelte
- ใช้ **WebSocket Hub** สื่อสารสถานะคิวงานระหว่างเซิร์ฟเวอร์กับหน้าจอคลังสินค้า
- ใช้ **Redis** เป็นชั้นแคชเพื่อลดภาระฐานข้อมูล และใช้ **MySQL** เป็นแหล่งข้อมูลหลัก

โครงการนี้ไม่ใช้คิวข้อความแบบ RabbitMQ

## 4. ความต้องการที่ไม่ใช่การทำงานของระบบ (Non-functional Requirements)

รหัส NFR ใช้ชุดเดียวกับเอกสาร PMP ข้อ 2.2

### 4.1 ส่วนต่อประสานผู้ใช้ (User Interface)

ออกแบบด้วย Responsive Web Design รองรับคอมพิวเตอร์ แท็บเล็ต และหน้าจอแสดงคิวในคลังสินค้า ส่วนติดต่อผู้ใช้พัฒนาด้วย Svelte และ Tailwind CSS ตามเอกสารการออกแบบซอฟต์แวร์ (SDD)

### 4.2 การใช้งานง่าย (Usability and Ease of Use)

ระบบแสดงเมนูและฟังก์ชันตามบทบาทของผู้ใช้ (RBAC) ผู้ใช้สามารถเปลี่ยนรหัสผ่านได้ด้วยตนเอง หน้า Queue Display เปิดใช้งานบนจอคลังสินค้าได้โดยไม่ต้องฝึกอบรมซับซ้อน

### 4.3 ประสิทธิภาพ (Efficiency)

ใช้ Redis ในการแคชข้อมูลเพื่อเพิ่มความเร็วในการเข้าถึง และลดการโหลดของฐานข้อมูล MySQL ตามเกณฑ์ REQ-NFR-02 (ผู้ใช้พร้อมกันไม่น้อยกว่า 50 คน และเวลาตอบสนองของ API เฉลี่ยต่ำกว่า 500 ms)

### 4.4 ความน่าเชื่อถือ (Reliability)

ระบบมีความเสถียรตาม REQ-NFR-01 โดยมี Uptime ไม่น้อยกว่า 99.5% ต่อเดือน สำรองข้อมูล MySQL ตามรอบในแผน SCM และสามารถ Restore กลับคืนได้ภายใน 1 ชั่วโมง ตาม REQ-NFR-04
